# RealSense D455 ↔ Livox Mid-360 checkerboard calibration

## Current Phase 1 status

The authoritative validation is `PHASE1_VALIDATION.md`, generated by
`scripts/phase1_required_validation.py`. It implements the mentor-requested
non-circular, point-wise reprojection test on real data.

The current saved internal transform is **not yet accepted** under the
project-defined rule that at least 99% of independently selected valid LiDAR
returns must have Euclidean reprojection error at or below 2 pixels at every
distance.

These percentages mean only the fraction of evaluated measured LiDAR returns
satisfying a declared pixel-error threshold. They are not called "calibration
accuracy," and this project makes no "100% calibration accuracy" claim.

## Real public dataset

External testing uses the non-synthetic [ACSC camera–LiDAR calibration
dataset](https://github.com/HViktorTsoi/ACSC). Its official sample archive is
[available here](https://drive.google.com/file/d/1hgV-aH_RSsL1geHDSIlwwvqrMy6ED56K/view).
The sample contains 21 real 2048×1536 RGB frames, paired measured N×4
XYZ-reflectance point clouds, calibration files, and point-cloud ROIs.

Public and internal results are separate experiments. No combined overall
percentage is calculated. The current ACSC held-out split also fails the
project rule; see `PHASE1_VALIDATION.md` for the result and extractor
limitations.

## Reproduce the corrected validation

Extract the internal ROS 2 bags to:

```text
data/raw/dataset01 14.5feet/
data/raw/dataset02 7.25feet/
data/raw/dataset03 22.2feet/
```

Download and extract the ACSC sample so it contains:

```text
data/public/acsc/sample/images/
data/public/acsc/sample/pcds/
data/public/acsc/sample/ROIs/
data/public/acsc/sample/intrinsic
data/public/acsc/sample/distortion
```

Then run:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/calibrate.py
.venv/bin/python scripts/phase1_required_validation.py
```

`scripts/validate.py` is retained as a compatibility launcher for the same
corrected validation.

Main generated evidence:

- `outputs/phase1_validation/phase1_validation_report.json` — complete
  machine-readable definitions, parameters, splits, per-frame records, metrics,
  provenance, and limitations;
- `outputs/phase1_validation/internal_multiframe_metrics.csv` — requested
  three-distance summary table;
- `outputs/phase1_validation/internal_calibration_parameters.yaml` — K, D,
  resolution, R, t, 4×4 transform, and frame convention;
- `outputs/phase1_validation/qualitative/` — nine examples, each with a
  lossless original-pixel RGB copy, a separate mask, and a projection/error
  figure.

## Evaluation design

Internal returns are frozen using only the Livox point cloud: a fixed metric
ROI, robust board-plane fit, known 0.30×0.45 m physical extent, and an interior
margin. The RGB checkerboard mask never selects or rejects evaluation returns.
After selection, the camera checkerboard geometry supplies the reference pixel
for the same physical board coordinate.

For projected pixel \((u_i,v_i)\) and reference pixel \((u_i^*,v_i^*)\), the
reported error is:

```text
e_i = sqrt((u_i - u_i*)^2 + (v_i - v_i*)^2)
```

"Strict alignment" means both projections round to the same raster pixel.
Continuous exact match is also recorded using a numerical tolerance of
`1e-9 px`; it is not substituted for the practical 2-pixel acceptance rule.

The raw RGB arrays remain at their recorded resolution and are never resized,
warped, deblurred, super-resolved, or regenerated. Masks are separate
visualization/annotation artifacts and do not participate in selection or
metric computation.

## Calibration model

No ML or DL model estimates the rigid transform. The calibration uses measured
checkerboard geometry, the D455 `CameraInfo` intrinsic model, robust LiDAR plane
fitting, OpenCV PnP, and nonlinear multi-range extrinsic refinement. Projection
uses:

```text
p_camera_color_optical = R_camera_lidar * p_livox + t_camera_lidar
[u, v] = project(K, D, p_camera_color_optical)
```

The optional MLP reflectivity classifier and downstream perception adapters in
this repository are separate experiments. Their cell-classification or
white-square precision values are not calibration accuracy and are not used in
the corrected Phase 1 acceptance decision.

## Known limitations and next action

Each internal bag contains one mostly static board pose. Ten synchronized
frames per distance give repeatability evidence, not ten geometrically
independent poses. The 14.5 ft and 22.2 ft checkerboards are only tens of pixels
wide, so their outer boundaries are manually annotated in the original image.
All three internal distances also participated in the existing transform fit,
so this is in-recording validation rather than unseen-capture generalization.

The failures are systematic across frames. The defensible next step is to
re-record a larger, sharp checkerboard at multiple positions and tilts at each
distance, keep the sensor rig fixed, calibrate on a training subset, and reserve
separate 22–30 ft captures for held-out validation. The transform must not be
declared complete until the corrected script passes every required distance.
